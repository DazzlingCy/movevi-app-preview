用途：产品、设计、研发、测试评审会决策记录

> 本清单只收录会影响范围、流程、数据或验收口径的事项。未拍板前，研发与设计按“默认建议”估算和出稿；评审结论应同步回写 PRD。

## P0｜必须在需求评审前确认

### 1. 极简实验与老版功能的关系

- 决策问题：新项目是否严格按方案隐藏活动、积分、光迹值、金币、任务、排行榜、勋章、抽奖和签到等一级功能，还是继续保留老版的主要功能入口？
- 默认建议：采用严格极简灰度实验；老版数据与能力保留以便回滚，但不进入新版本主导航。
- 影响范围：信息架构、页面数量、实验有效性、研发工作量和回滚方案。
- 责任人：产品负责人。

### 2. 城市推进方式

- 决策问题：采用唯一线性旅程序列，还是每完成一城后从四个候选城市中自由选择？
- 默认建议：以确定性序列计算后续四个未完成城市，用户可四选一；第一座标记“推荐”。
- 影响范围：城市状态机、候选算法、地图展示、数据结构和内容运营。
- 责任人：产品负责人、内容负责人。

### 3. 有效完成路线的判定口径

- 决策问题：什么条件下跑步记录可以推进路线与城市进度？
- 默认建议：完成目标距离的 90% 及以上且有效运动时长不少于 10 分钟；异常速度或设备判定无效的记录不推进。
- 影响范围：进度计算、反作弊、售后申诉、数据埋点和验收测试。
- 责任人：产品负责人、算法/运动数据负责人。

### 4. 首发城市目录与顺序

- 决策问题：是否采用 PRD 中的 20 城目录与默认顺序？
- 默认建议：北京 → 上海 → 东京 → 巴黎 → 纽约 → 伦敦 → 罗马 → 柏林 → 莫斯科 → 迪拜 → 开罗 → 孟买 → 曼谷 → 新加坡 → 悉尼 → 洛杉矶 → 多伦多 → 里约热内卢 → 杭州 → 西安。
- 影响范围：内容生产、地图点位、候选算法、初始化与测试数据。
- 责任人：产品负责人、内容负责人。

### 5. 新用户第一站

- 决策问题：新用户默认从北京开始，还是根据地区、语言或兴趣推荐？
- 默认建议：V1.0 统一从北京开始，减少实验变量；个性化首站放入后续版本。
- 影响范围：新手引导、初始化数据、实验分组和首日转化率。
- 责任人：产品负责人、数据负责人。

### 6. “未知路线”揭晓时机

- 决策问题：点击后即永久揭晓，还是开始跑步/完成前置路线后揭晓？
- 默认建议：点击可发现路线后立即揭晓并持久化，用户可以返回后再开始跑步。
- 影响范围：路线状态、接口、埋点、返回路径和好奇心驱动强度。
- 责任人：产品负责人、交互设计师。

## P1｜必须在开发排期前确认

### 7. 灰度比例、周期与成功阈值

- 决策问题：实验覆盖人群、运行周期以及继续放量/回滚的阈值是什么？
- 默认建议：10% 新用户 + 5% 活跃老用户，连续运行 4 周；按 PRD 1.1.3 的指标阈值决策。
- 影响范围：实验平台、样本量、统计显著性、发布时间和回滚机制。
- 责任人：产品负责人、数据负责人、研发负责人。

### 8. 老用户历史资产的迁移与展示

- 决策问题：老用户城市、路线、积分、勋章等历史资产在新项目中如何处理？
- 默认建议：城市、路线和跑步记录完整迁移；积分、勋章等保留在老版只读账户记录，不进入极简主流程。
- 影响范围：数据迁移、账号兼容、用户沟通、客服话术和回滚。
- 责任人：产品负责人、后端负责人、客服负责人。

## P2｜可在详细设计阶段补充

### 9. 跑步草稿保留时长

- 决策问题：中断或闪退后的未提交跑步记录保留多久？
- 默认建议：本地与服务端草稿保留 24 小时，超时自动清理并记录原因。
- 影响范围：异常恢复、存储、隐私和边界测试。
- 责任人：产品负责人、技术负责人。

### 10. 日志与分析数据生命周期

- 决策问题：设备故障日志和匿名分析明细分别保留多久？
- 默认建议：设备故障日志 30 天，匿名分析明细 180 天，并遵循现有隐私政策与删除流程。
- 影响范围：合规、存储成本、问题追踪和数据分析。
- 责任人：法务/隐私负责人、数据负责人。

### 11. V1.1 内容付费方式

- 决策问题：极简旅程验证后，是否通过城市包、会员或其他方式商业化？
- 默认建议：V1.0 不设置付费入口，先验证旅程推进对活跃和完课的增量价值。
- 影响范围：远期商业化，不阻塞 V1.0。
- 责任人：产品负责人、商业化负责人。
