## 1. 背景与目标

MOVEVI APP 2.1 在上一版本的基础上，优化设备连接后的反馈、城市路线选择体验、路线详情信息和全球排行榜展示。

本次调整内容：

| 序⁠号 | 调⁠整⁠项 | 调整内容 | 调整目的 |
| --- | --- | --- | --- |
| 1 | 设⁠备⁠连⁠接⁠反⁠馈 | 用户在未连接设备时打开 APP，APP 自动发起设备连接；连接成功后新增设备已连接弹窗，明确展示已连接设备，并提供关闭弹窗和查看设备两个入口。 | 避免用户未感知自动连接结果，明确设备连接状态。 |
| 2 | 城⁠市⁠路⁠线⁠卡⁠片 | 将城市路线调整为横向卡片结构，通过封面展示、卡片描边、状态配色及按钮高亮强化视觉层次。 | 提升路线浏览的沉浸感，让用户清晰区分已完成、已解锁和未解锁路线。 |
| 3 | 路⁠线⁠信⁠息⁠展⁠示 | 在路线卡片和路线详情中补充跑过人数、评分、预计运动数据及路线信息，通过信息分组、图标辅助、字号层级和合理留白优化视觉呈现。 | 突出关键数据与路线特色，提升页面精致度和信息可读性。 |
| 4 | 全⁠球⁠排⁠行⁠榜 | 将跑步机榜与走步机榜合并为统一的全球排行榜，不再按设备类型区分榜单，并突出环球等级、前三名和当前用户排名。 | 不同设备的等级获取难度一致，无需区分榜单；合并后可避免同一用户存在两套排名带来的理解成本。 |

本文件只描述 本次调整的页面。

## 3. 改动页面说明

### 3.1 01｜设备已连接弹窗

**调整目的**

用户完成设备连接后，通过弹窗确认连接结果，避免用户无法判断设备是否已经就绪。

**展示内容**

| 元素 | 说明 |
| --- | --- |
| 背景遮罩 | 保留当前首页作为背景并整体降暗，弹窗打开时背景不可操作 |
| 设备插画 | 展示跑步机图形、连接成功勾选和状态光晕 |
| 设备名称 | 展示当前连接设备名称，如 `TS3P_01D60` |
| 连接状态 | 固定文案“设备已连接” |
| 说明文案 | “设备已就绪，开启你的运动之旅吧。” |
| 主按钮 | “知道了” |
| 次级入口 | “查看我的设备” |

**交互说明**

- 设备连接成功并完成状态保存后展示弹窗。
- 点击“知道了”关闭弹窗，返回当前首页状态。
- 点击“查看我的设备”进入现有“我的—设备”页面。
- 弹窗打开时禁止操作和滚动背景页面。
- 同一次连接成功事件只展示一次弹窗，不重复叠加。
- 如果弹窗展示期间设备断开，应关闭成功状态，并沿用现有设备断开提示。

### 3.2 02–04｜城市路线

02、03、04 为同一城市路线页面的不同路线状态，公共页面结构保持一致，只调整当前居中路线卡片的状态和操作。

#### 3.2.1 页面公共结构

| 区域 | 展示内容与交互 |
| --- | --- |
| 城市头图 | 展示城市封面、英文名、中文名、路线数量和路线总里程 |
| 返回按钮 | 返回进入城市路线页之前的页面 |
| 路线概览 | 点击进入该城市现有路线概览页 |
| 页面标题 | 展示“选择路线”和“按路线顺序探索” |
| 路线卡片 | 按后台配置顺序横向排列；当前卡片完整展示，相邻卡片局部露出 |
| 路线信息 | 展示路线序号、分类、状态、封面、名称、主要景点、距离、预计时长和景点数 |
| 跑者信息 | 展示最多 3 个跑者头像和“XXX 人跑过” |
| 路线评分 | 展示路线评分；暂无评分时显示 `--` |

**路线数量与排序**

- 每座城市的路线数量不固定，取后台当前发布的有效路线数量。
- Figma 中“10 条路线”及 08、09、10 等序号仅为示例，不得固定写入页面逻辑。
- 路线按后台配置的顺序展示。
- 用户横向滑动、拖动或使用方向键切换路线，停止操作后居中最近卡片。
- 返回路线列表时，应恢复用户离开前查看的路线卡片。

**跑过人数口径**

- 路线跑过人数按用户和路线去重。
- 用户只要在该路线产生过至少一条有效运动记录，无论路线有没有完成，均计入跑过人数。
- 同一用户重复运动同一路线只计 1 人。
- 仅浏览路线、进入详情、进入运动页但没有保存有效运动记录时不计入。

#### 3.2.2 路线状态差异

| 页面状态 | 状态标签 | 卡片表现 | 操作文案 | 点击结果 |
| --- | --- | --- | --- | --- |
| 02 已完成 | 绿色“已完成” | 绿色描边及完成态内容区 | “已完成 · 再跑一次” | 进入 05，可再次开始该路线 |
| 03 已解锁 | 紫色“已解锁” | 紫色描边及高亮主按钮 | “开始这条路线” | 进入 05，可开始路线 |
| 04 未解锁 | 灰色“未解锁” | 降低封面和操作区对比度 | “未解锁 · 查看详情” | 进入 05 只读状态，不可开始路线 |

**补充说明**

- 已完成路线再次运动时，可以生成新的运动记录，但不得重复增加首次完成类数据。
- 未解锁路线允许查看封面、景点、预计距离和时长，但任何入口都不能开始运动。
- 点击路线卡片或卡片底部操作区均进入路线详情页，开始运动统一从详情页触发。
- 后台路线状态变化后，页面应同步更新状态标签、颜色和操作文案。
- 路线封面加载失败时使用默认路线封面，不影响查看详情。

### 3.3 05｜路线详情页

**调整目的**

在开始运动前集中展示单条路线信息，帮助用户确认路线内容、预计运动量和当前可操作状态。

**展示内容**

| 区域 | 说明 |
| --- | --- |
| 路线头图 | 展示路线封面和返回按钮 |
| 路线标题 | 展示当前路线名称 |
| 跑者信息 | 展示最多 3 个跑者头像和“XXX 人跑过” |
| 预计数据 | 展示预计里程、预计时长、预计消耗和路线评分 |
| 路线景点 | 按顺序展示路线途经景点 |
| 路线简介 | 展示后台配置的路线介绍 |
| 评论按钮 | 进入现有路线评论页面 |
| 开始跑步 | 进入现有运动执行流程 |

**交互说明**

- 从城市路线卡片进入时，携带当前城市和路线信息。
- 点击返回后回到城市路线页，并恢复进入前的路线卡片位置。
- 已解锁和已完成路线可以点击“开始跑步”。
- 未解锁路线进入详情后只允许浏览，“开始跑步”按钮置灰并显示解锁提示。
- 未连接设备时点击“开始跑步”，进入现有设备连接流程；连接成功后返回当前路线。
- 点击开始前再次校验路线状态，避免使用缓存绕过路线锁定条件。

**跑过人数说明**

- 跑过人数统计口径与城市路线卡片一致。
- 同一路线在卡片页和详情页必须显示同一人数。
- Figma 中 `3,860 人跑过` 和 `29 人跑过` 均为示例数据，不代表两个统计口径。
- 跑过人数为 0 时，不展示头像，文案显示“暂无跑者记录”。

### 3.4 06｜全球排行榜

**调整目的**

简化排行榜页面结构，突出环球等级排名、领先用户和当前用户所在位置。

**展示内容**

| 区域 | 说明 |
| --- | --- |
| 页面标题 | 固定文案“全球排行榜” |
| 返回按钮 | 返回世界页 |
| 规则按钮 | 打开现有排行榜规则弹窗 |
| 前三名 | 展示头像、昵称、名次和环球等级；第 1 名居中突出 |
| 普通榜单 | 从第 4 名开始展示名次、头像、昵称和环球等级 |
| 我的排名 | 底部固定展示当前用户的名次、昵称和环球等级 |

**交互与展示说明**

- 2.1 页面不展示跑步机和走步机 Tab，只展示一份全球榜单。
- 榜单按环球等级从高到低排列；同等级按已完成路线数从高到低排列；仍相同则并列。
- 当前用户不在当前加载范围时，仍通过底部“我的排名”展示个人位置。
- 当前用户未上榜时显示“未上榜”，不得生成虚构名次。
- 点击“规则”打开现有规则弹窗，关闭后恢复之前的榜单滚动位置。
- 榜单为空时沿用现有空状态；加载失败时显示重试，不得用空状态替代错误状态。
- 头像加载失败使用默认头像，昵称缺失使用产品默认称呼。
